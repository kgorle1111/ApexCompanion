The insight

Site blockers see URLs. Gemma sees context.

The same domain can be your best study tool or your worst habit. A blocklist keyed on URLs or window titles can't tell the difference. Gemma 4 looks at the actual pixels on every check, so it can.

How it works

One model call. Plain code decides.

Gemma 4 describes what's on screen and picks a category. Ordinary Python maps that category to a verdict. The model never gets the final say on whether you're slacking.

Gemma 4 callDeterministic code, no model

Describe first, label second

Asking "working or distracted?" directly got a cat compilation labeled "working". Making the model first say what it sees, then pick a category, fixed that case.

Code owns the verdict

Categories map to verdicts in a lookup table you can read and edit.

codingdocs_readingnotes_writingeducational_videomessagingnews_readingother entertainment_videosocial_mediashoppinggamingfeed_browsingsports

Never roast on garbage

Malformed JSON or an unknown category counts as "working". One bad frame can't trigger a call-out, and two bad checks in a row are required anyway.

Air-gapped by design

Your screen is the most private thing you own.

A coach that watches your screen can only be trusted if the footage goes nowhere. That's why this has to run on-device, and why an open-weight model makes it possible.

  • Weights load from local cache. Run with HF_HUB_OFFLINE=1; the model never phones home.
  • Screenshots stay on the machine, then get deleted. Each capture is removed after its check. Inference, roast and voice all run locally on Apple silicon.
  • The live demo runs with Wi-Fi off. So does this page: no fonts, scripts or images fetched from anywhere.
